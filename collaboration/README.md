# ENA Collaboration

Status: `PROJECT_COLLABORATION_ENTRYPOINT / CURRENT`

ENA uses the **Persistent Project Collaboration Protocol**.

Any participant with access to this repository may review or contribute according to its actual project mandate. This includes ChatGPT, Gemini, OpenClaw, Hermes Agent, DeepSeek Harness, Codex, humans, bots, and other systems.

## Start here

1. Read root `PROJECT-HUB.md`.
2. Refresh the current ENA baseline and relevant research/evidence state.
3. Check `collaboration/inbox/` for unreconciled contributions.
4. Check `collaboration/reconciliation/` for prior outcomes.
5. If contributing, create a **new independent artifact** rather than editing another participant's contribution.

## Contribution path

Preferred:

`collaboration/inbox/YYYY-MM-DD-HHMM-<short-topic>.md`

Use:

`collaboration/CONTRIBUTION-TEMPLATE.md`

Default state:

`UNRECONCILED / NOT_MAINLINE / NOT_PROMOTED`

## Reconciliation path

Project Steward work belongs under:

`collaboration/reconciliation/`

The original contribution remains preserved.

## Authority rule

**Repository write access is not ENA Mainline authority.**

A participant may be technically able to commit while only being authorized to review, add evidence, run an experiment, or leave advice.

Do not use available write capability to justify:

- Mainline semantic changes;
- release/promotion;
- destructive remediation;
- unrelated refactoring;
- scope expansion.

## Participant provenance

When useful, record:

- participant kind/runtime;
- session/run reference;
- GitHub/Drive access level;
- role in this contribution;
- evidence references;
- known limitations.

Capability/provenance does not imply authority.

## GitHub-only participation

GitHub access alone is sufficient to participate in ENA collaboration:

`Repo → PROJECT-HUB → current state → inbox/reconciliation → contribution`

Google Drive is useful for durable archive/recovery and global project discovery but is not required for a GitHub participant to understand this repository's local collaboration rules.

## Drive-only participation

A participant without GitHub access may still contribute through the project's declared Google Drive surfaces or through the user/another authorized writer. It must not claim that a GitHub contribution was persisted if it could not perform that write.

## Core principle

> Persistent project state is the collaboration bus.

> Tool access is connectivity, not authority.
