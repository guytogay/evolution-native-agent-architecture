## Inference

- **The constitutional invariants and claim/evidence discipline are genuinely valuable**: they changed actual behavior this session (identity verification before assertion; unknown-preservation; negative-evidence retention).
- **Enforcement density is the weakest point**: most governance is prompt-level self-governance; only a thin slice is machine-checked. "Schema PASS ≠ semantic truth" is honest, but the practical consequence is that enforcement strength is far below what the vocabulary (38/71/14/5) suggests.
- **Taxonomy is a map, not a mechanism**: an agent can fill capability states, role qualifications, and stage labels correctly without changing behavior (box-checking risk). State enums do not produce protection by themselves.
- **Governance should measure its own rent**: ENA-CON-038 requires governance to be value-accountable, but the framework has no built-in instrument for its own cost/friction. First-adoption overhead was acceptable one-time, but proportional governance (CON-034) needs a concrete LITE path with a minimal artifact set, otherwise LITE/STANDARD/HIGH_ASSURANCE are just declarations.
- **Machine-checkability should be extended to the governance core**: Self-Positioning capability states and the Active Governance Set have enumerated vocabularies (UNKNOWN/UNVERIFIED/VERIFIED_AVAILABLE/... ; ACTIVE/DORMANT/...) that are trivially schema-validatable but currently are not.

## Suggestion / question

1. Add machine-checkable schemas + validator modes for (a) Self-Positioning capability states and (b) Active Governance Set states — the governance core is currently the least machine-verified part.
2. Define a concrete LITE adoption path with a tiny artifact set (e.g., 3-line positioning + 1 claim + no AGS file) so proportional governance is real, not just declared.
3. Publish the validator's own test cases (HAR-style or plain fixtures) as part of the release, so "validator works" is itself evidenced.
4. Define an explicit Beta→Mainline gate (field-experience count, counterexamples handled, host diversity, tool coverage) so Beta is a state machine, not a permanent label.
5. Consider a canonical-pointer field (pinned commit SHA) in `CURRENT-BASELINE.yaml` so "current" is resolvable without cloning history (ties to the identity-drift finding).
