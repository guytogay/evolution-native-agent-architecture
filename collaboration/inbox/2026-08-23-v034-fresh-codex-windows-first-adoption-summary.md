## Main reconciliation finding 1 — durable surface presence != effective loaded content

This Host adds an important capacity/order dimension to persistence.

The adopter chose to place the compact kernel near the front of an already-large global instruction file because it believed later bytes could be truncated by the Host's instruction loading limit.

Together with the fresh Hermes skill case, this supports a more general distinction:

`DURABLE_OBJECT_EXISTS != RELEVANT_BYTES_LOADED != SEMANTICS_AVAILABLE`

A valid first-adoption projection should account, where material, for actual instruction capacity, precedence/order, truncation, selective loading, routing, and other mechanisms that determine the effective loaded slice — not only whether a file or memory object exists.

Classification: `CORRECTION_CANDIDATE / CROSS_HOST_RELEVANT`.

Potential future clarification:

`Verify the effective loaded surface, not merely durable storage.`

## Main reconciliation finding 2 — low-cost boundary-test protocol remains missing

The report praised the `WRITTEN != LOADED != INTERPRETED != SALIENT != APPLIED` distinction but found no Host-neutral, low-cost protocol for evidencing those transitions. Its attempted fresh-run boundary was blocked by a Host-specific executable-launch failure, leaving the correct result UNKNOWN.

This recurs with Hermes/OpenClaw field work. Opportunity: define a lightweight evidence vocabulary/protocol for natural fresh-session boundaries without requiring a fake production task, universal tooling, or a single Host mechanism.

Classification: `CORRECTION_CANDIDATE / CROSS_HOST_RECURRENT`.

## Main reconciliation finding 3 — Constitution weight is now recurrent among fresh adopters

This fresh Codex independently found the 38-item Constitution cognitively heavy/repetitive while still treating it as cold authoritative reference rather than deleting its invariants.

This differs materially from the earlier fresh Hermes semantic failure: Codex did not report that inconvenient invariants could be removed from effective semantics.

Opportunity: clarify the architecture as:

`all universal invariants remain binding; not all must remain literally always-loaded`.

The recurrence supports documentation/packaging simplification, not automatic deletion or weakening of constitutional semantics.

Classification: `DOCUMENTATION_CORRECTION_CANDIDATE / CROSS_FRESH_ADOPTER`.

## Main reconciliation finding 4 — canonical-history/privacy/legal-erasure boundary is under-specified

The report identified tension between append-only-in-meaning / occurrence-truth preservation and privacy deletion, secret-leak remediation, or legally required retention/deletion limits.

Current section 5.3 clearly separates recovery state from occurrence history and requires material occurrence truth to remain monotonic/recoverable where possible, but the canonical text does not expose a sufficiently explicit privacy/legal-redaction exception/transform contract for ordinary adopters.

This should not be resolved by silently rewriting history or by treating privacy law as subordinate to an architecture slogan.

Opportunity: define how governed redaction/deletion, secret revocation/removal, minimization, tombstones/metadata, legal retention limits, and provenance can coexist with truthful non-revisionist history claims.

Classification: `SEMANTIC_BOUNDARY_HYPOTHESIS / HIGH_VALUE_CORRECTION_CANDIDATE`.

## Main reconciliation finding 5 — self-governance recursion has partial controls but weak termination semantics

The report noted that the self-mutation gate is itself mutable and can trigger recursive review.

Current ENA partially addresses this through slower constitutional/recovery-root evolution and governance/meta-evolution triggers. Therefore this is not evidence that recursion is completely unhandled.

Residual question: what establishes that governance of governance is sufficient and further meta-review should stop for the current consequence envelope?

Opportunity: make termination/convergence semantics more explicit without creating an infinite hierarchy of gates or mandatory meta-ceremony.

Classification: `FIELD_HYPOTHESIS / SEMANTIC_TERMINATION_BOUNDARY`.

## Main reconciliation finding 6 — organism boundary can become an unbounded veto

The report challenged the phrase `Never risk the organism` because the effective organism/project/Host consequence boundary is not sufficiently operationalized for adopters.

Current contracts distinguish project/organism identity from Agent/Host/model/route, but a fresh adopter can still lack a practical answer to: what exactly is the protected organism for this decision, and what lies outside it?

Opportunity: clarify that organism/protected-subject scope must be evidenced and bounded, not expanded rhetorically to veto all risk or all change.

Classification: `SEMANTIC_BOUNDARY_HYPOTHESIS / CORRECTION_CANDIDATE`.

## Main reconciliation finding 7 — profile calibration remains judgment-heavy

Do not respond by inventing one universal numeric risk score. Current CAP-070 explicitly avoids forcing one universal scalar. Prefer real examples/counterexamples, bounded consequence dimensions, and evidence-driven escalation/de-escalation if further recurrence supports a change.

## Main reconciliation finding 8 — governance-rent stop condition is soft, not absent by accident

The report criticized the lack of a rent metric/stop condition.

Current ENA already requires lowest-cost sufficient intervention and says stable systems should become quieter; CAP-070 explicitly avoids a universal scalar. Therefore lack of a single numeric rent measure is intentional.

Residual opportunity: operationalize a clearer stopping principle such as `required property sufficiently protected for the current consequence envelope, with remaining uncertainty/residual risk honestly bounded -> stop adding governance`.

This is a candidate clarification, not evidence that a universal scalar should be added.
