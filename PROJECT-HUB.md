# ENA Project Hub — Legacy Pointer

Status: `COLD_COMPATIBILITY_POINTER / NOT_LIVE_PROJECT_STATE`

This file is retained because historical records and old links point here. It is no longer the live project-management hub.

## Live entrypoints

- **Current adoption truth:** `releases/current/CURRENT-BASELINE.yaml`
- **Effective Current package:** `releases/current/`
- **Current project/research status:** `NOW.md`
- **Open work / field evidence:** GitHub Issues
- **History:** Git history and the specific evidence/research artifact needed for the question

Do not copy release run IDs, branch inventories, current handoff records, progress snapshots, or active-Issue lists into this file.

## Why this changed

The previous hub accumulated adoption routing, session takeover, release proof, branch state, research direction, clean-room state, next actions, and release errata in one surface. Keeping those facts synchronized created project-management work without reliably increasing ENA's evolutionary value.

ENA now uses one small live status surface and retrieves deeper history only when a consequential decision requires it.

Historical takeover/handoff/reconciliation files remain available as cold occurrence truth. They are not mandatory reading for a new session.

> Preserve history; minimize live coordination state.
