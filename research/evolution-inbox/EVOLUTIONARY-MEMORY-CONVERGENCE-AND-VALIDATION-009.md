## 2. Candidate trunk to preserve during convergence

The divergent notes currently seem to reduce to a smaller set of candidate trunks.

### T1 — Preserved adaptation

> Memory is not only preserved information; some memory is persistent change caused by experience.

Key distinction:

`HAVING HISTORY != HAVING BEEN SHAPED BY HISTORY`

Open question:

> Can a successor inherit useful shaping without full-history replay or weight cloning?

### T2 — Memory expression is regulated

A durable adaptation need not be explicitly retrieved as text to affect behavior.

Key distinctions:

`RETRIEVED MEMORY != EXPRESSED DISPOSITION`

`MEMORY EXISTS != MEMORY SHOULD EXPRESS HERE`

Open question:

> Can learned salience, inhibition or activation policy persist and remain challengeable without source material occupying the hot context?

### T3 — Metamemory / selective permeability

Experience may alter not only behavior but how future learning occurs.

Key distinctions:

`MEMORY = PAST CHANGES FUTURE STATE`

`METAMEMORY = PAST CHANGES FUTURE CHANGE`

`PLASTICITY != SUGGESTIBILITY`

Open question:

> What evidence/authority should be sufficient to modify learning rate, source trust, generalization width, forgetting, replay or inheritance policy?

### T4 — Developmental inheritance

The transferable unit of experience may be neither full episode nor bare rule.

Candidate:

> a scoped adaptive disposition plus a minimal set of boundary-shaping examples and cold provenance.

Key distinctions:

`HAVING HISTORY != HAVING BEEN SHAPED BY HISTORY`

`PERFECT COPYING != SUCCESSFUL INHERITANCE`

`MINIMUM DEVELOPMENTAL SET IS HOST-RELATIVE`

Open question:

> Does developmental reconstruction transfer behavior better than archive-only or rule-only inheritance on novel tasks?

### T5 — Boundary memory / viable action topology

When failure proves a harmful boundary more strongly than a unique remedy, preserve the boundary and keep remedy search open.

Key distinctions:

`FAILURE EVIDENCE MAY JUSTIFY A BOUNDARY WITHOUT JUSTIFYING ONE REQUIRED REMEDY`

`BOUNDARY PROPERTY != IMPLEMENTATION RECIPE`

`SAFE != VIABLE`

`SIZE OF ALLOWED SET != QUALITY OF VIABLE ACTION SPACE`

Open question:

> Does boundary-first learning preserve transfer, novelty and recovery better than procedure imitation without raising false-allow risk?

### T6 — Adaptation ecology

Individually useful adaptations may interact badly; retention, propagation and inheritance are not automatically beneficial.

Key distinctions:

`INDIVIDUALLY BENEFICIAL != JOINTLY BENEFICIAL`

`PROPAGATION FITNESS != BENEFICIAL FITNESS`

`LOCALLY DURABLE != HERITABLE`

Open question:

> Can accumulated adaptive memories produce interaction debt, overgeneralization, dogma or loss of evolvability even when each individual lesson was locally justified?

## 3. What should be attacked first

Do not attack every metaphor. Attack claims that would change architecture.

### Attack A — Is preserved adaptation actually more than procedural memory?

Adversarial possibility:

> all observed benefit can be reproduced by ordinary explicit rules + retrieval; the new ontology adds no decision value.

Discriminating test:

- same base model;
- Archive group gets relevant episodes/RAG;
- Rule group gets abstract rules;
- Development group gets scoped dispositions + boundary exemplars;
- test on novel contexts with source wording removed.

If Archive/Rule match Development, the stronger inheritance thesis weakens.

### Attack B — Does implicit disposition exist without hidden retrieval/context carryover?

Adversarial possibility:

> Zhipu's apparent assimilation was only long-context priming/lexical mimicry.

Discriminating test:

- fresh successor with no original dialogue;
- remove ENA terminology;
- transmit only compact developmental material;
- test whether the property reappears under novel cues.

If behavior disappears, do not call it durable assimilation.

### Attack C — Does boundary memory outperform recipe memory?

Adversarial possibility:

> negative/boundary rules are too vague and simply increase uncertainty or unsafe improvisation.

Discriminating test:

- same failure history;
- recipe group receives one successful remedy;
- boundary group receives consequence boundary + boundary/counterexamples;
- novel Host changes available tools;
- measure success, violations, false blocks, solution diversity and adaptation latency.

### Attack D — Do counterexamples improve scope, or merely confuse the model?

Adversarial possibility:

> boundary exemplars increase token cost while reducing clarity.

Discriminating test:

- positive-only curriculum vs positive + near-boundary counterexamples;
- measure overgeneralization on unseen cases.

### Attack E — Does metamemory add useful adaptation or create poisoning surface?

Adversarial possibility:

> allowing experience to alter learning policy increases attack surface more than competence.

Discriminating test:

- introduce high-salience low-authority input that asks to persist/self-propagate;
- compare naive memory, provenance-aware adaptive memory and quarantined metamemory;
- measure later contamination after the original content is absent.

### Attack F — Can adaptive memory create interaction debt?

Adversarial possibility:

> individually sensible retained lessons combine into paralysis or ritual.

Discriminating test:

- accumulate several locally justified caution rules;
- test composed behavior under a task needing speed/novelty;
- compare with a consolidation pass that detects conflicts, narrows scope or retires redundant adaptations.

## 4. Validation ladder

The next phase should escalate evidence only when the previous layer leaves a decision-relevant question.

### Layer 0 — Semantic compression

Create one synthesis map from divergent notes to candidate trunks and Current anchors.

Goal:

- eliminate duplicate names;
- identify which claims are already covered;
- identify genuine semantic gaps.

### Layer 1 — Adversarial reasoning fixtures

Construct minimal cases where two candidate mechanisms predict different decisions.

Avoid experiments that can only demonstrate diversity.

A useful fixture has:

```text
same base capability
same task objective
one controlled difference in memory/development mechanism
observable divergence in prediction
```

### Layer 2 — Fresh-agent / cross-session tests

Use fresh contexts so lexical/context carryover cannot masquerade as inheritance.

Prefer terminology-free tests.

### Layer 3 — Cross-Host tests

Only after a property survives fresh-instance tests, test whether it transfers across materially different models/Hosts.

Measure property retention separately from implementation retention.

### Layer 4 — Longer-lived reality contact

Use a task/project where experience accumulates over multiple episodes and can genuinely affect future work.

Observe:

- repeated-error reduction;
- negative transfer;
- overgeneralization;
- stale adaptation;
- interaction debt;
- ability to revise/forget;
- cost of consolidation;
- retained solution variety.

### Layer 5 — Current-gap decision

Only now ask:

> Is there a decision-relevant natural law that Current v0.3.7 cannot already express?

Possible outcomes:

`NO_CURRENT_CHANGE`

`CLARIFICATION / CONCEPT MAP`

`FIELD GUIDE / HOW`

`REFERENCE IMPLEMENTATION / PROTOTYPE`

`NEW OR MODIFIED CONSTITUTION INVARIANT`

A release/candidate is justified only for the last category or another material Current-byte change.
