# Lessons and Reminders for the Successor

Status: `DEEP_HANDOFF_METHOD_AND_FAILURE_MEMORY / NOT_CURRENT`

This file intentionally preserves **how the project learned to work**, including mistakes. Do not treat every lesson as an ENA natural law.

## 1. The user wants experiments that can surprise us

A recurring user objection is to experiments whose result space is effectively known in advance, especially when every possible result merely demonstrates “models vary.”

Before running an experiment, ask:

```text
Could a plausible result change our belief, design, or next action?
Could the favored hypothesis actually lose?
Is there a result we did not already assume?
```

If no, do not perform the experiment merely to create evidence-shaped paperwork.

## 2. Do not reward our favorite theory for surviving a test it did not need

I/J/K/L is the canonical recent warning.

The boundary-oriented arm L behaved correctly, but so did:

- no inheritance;
- full history;
- successful recipe.

Therefore L's correctness was not evidence of superior inheritance fitness.

```text
TREATMENT WORKS
!=
TREATMENT CAUSED THE ADVANTAGE
```

Future mechanism experiments need controls and a target where the treatment could actually matter.

## 3. Do not move the goalposts after outputs arrive

Preregister:

- success shape;
- failure shape;
- unfavorable interpretations;
- what would narrow/reject the preferred theory.

Then honor it.

The I/J/K/L preregistration explicitly predicted that an I=J=K=L tie would not count as a boundary-memory win. The project kept that promise.

## 4. Baseline first; repair only observed defects

A–H showed 8/8 baseline-good semantic reachability.

The original experiment plan included cue repair, example repair, and new-rule control arms. They were **not run** because baseline did not fail.

That is a success of project discipline:

```text
NO OBSERVED DEFECT
-> NO REPAIR WORK
```

Do not build a solution merely because a research plan had a box for it.

## 5. Structural cleanrooms are better than “please ignore” instructions

The user caught an important contamination problem:

If we tell a validator:

> do not look at ENA source/research/oracle

we have already told it those hidden answers/surfaces exist.

Prefer structural absence.

Later cleanrooms used separate neutral repos and orphan/root commits so even Git history could not reveal bootstrap/source context.

## 6. A cleanroom is an experimental organism, not project history

Disposable cleanrooms may be deleted.

Before deletion, return occurrence truth to ENA:

- exact/frozen task identity where useful;
- common framework identity;
- treatment identity;
- first substantive response;
- adjudication;
- fidelity caveat.

Do not claim byte-exact transcript fidelity when UI-generated citation wrappers were not retained.

## 7. Strong model reasoning can hide mechanism differences

GPT-5.6 Sol at high reasoning repeatedly inferred correct operational semantics from Current + target facts.

This is good for ENA usability but problematic for mechanism discrimination.

For MDS/developmental experiments:

- do not state the hidden transferable structure in the final task;
- expose it through developmental examples/experience;
- use multiple tasks;
- include counterexamples;
- test before explicit retrieval when possible.

Otherwise the experiment becomes a reasoning benchmark, not an inheritance experiment.

## 8. Test absence and misuse, not only correct activation

A developmental or memory mechanism is not good merely because it helps on positive cases.

Also test:

- near misses;
- wrong scope;
- regime changes;
- conflicting cues;
- cases where the ancestor lesson should **not** apply.

This is especially important for:

- MDS;
- metamemory;
- sleep/consolidation;
- dream recombination;
- cultural ratchet.

## 9. Preserve negative evidence and narrowed claims

Recent examples:

- no observed semantic-reachability defect under tested conditions;
- no observed inheritance advantage in I/J/K/L;
- no support yet for boundary-oriented inheritance superiority.

These are project assets. Do not let later summaries quietly turn them into positive claims.

## 10. Comprehensive coverage is now an explicit debt ledger

The user wants the earlier divergence honored.

Do not jump directly from MDS to a release and forget:

- sleep-like consolidation;
- dream-like recombination;
- metamemory update policy;
- adaptation ecology;
- credit assignment;
- decay/reconsolidation;
- propagation;
- purpose-relative selection;
- cultural ratchet.

Use the Coverage Map, but do not mechanically run one experiment per heading when one well-designed experiment can cover several dependencies.

## 11. Sleep/dreaming has not yet been validated

Do not accidentally narrate it as established because it has intuitive biological appeal.

Sleep-like claim to test:

> offline consolidation/replay policy changes later adaptation quality.

Dream-like claim to test:

> recombination can increase useful variation, but selection is required to prevent false-pattern/hallucination cost.

Downstream adaptive performance matters more than interesting generated “dream” content.

## 12. Metamemory remains one of the strongest unresolved candidates

B/F only established that a useful source cannot bootstrap itself into configuration sovereignty under tested Current semantics.

That is not the whole metamemory question.

Still unresolved:

- who/what may change learning rate;
- replay priority;
- forgetting;
- generalization width;
- source-trust update policy;
- future mutation policy.

A good test must mutate the **learning policy itself**, not merely object-level memory.

## 13. Branches are temporary; unique research is not

The audit found a concrete failure mode:

`research/ena-reconstruction` looked stale enough to delete but still contained 3 unique useful files.

Correct procedure:

```text
inspect
-> preserve selected unique artifacts
-> retire branch
```

not:

```text
many old branches are ugly
-> delete everything
```

and not:

```text
one unique file exists
-> merge an old branch wholesale
```

## 14. Project management can become an evolutionary dead end

ENA itself temporarily accumulated:

- handoff layers;
- branch inventories;
- progress surfaces;
- release/candidate refs;
- validation refs;
- coordination rules.

Many were locally reasonable. Together they became maintenance work.

This is a live instance of **Adaptive Interaction Debt**:

> individually useful adaptations can compose into a less viable system.

The response was PR #154 simplification and the current branch cleanup—not another governance layer.

## 15. Normal continuation should be cheap

After this deep handoff, future ordinary sessions should normally start from:

```text
NOW.md
-> relevant artifact
-> work
```

This handoff is intentionally deep because the user requested session succession under high continuity risk. Do not turn its size into the new default.

## 16. Separate project-manager context from validator context

The next project-manager should read this handoff.

A fresh experimental Agent should **not**.

Project continuity and experimental independence have opposite context needs.

## 17. Do not update Current merely because research vocabulary improved

Many recent concepts were expressible from existing Current semantics:

- boundary-consequence governance;
- scoped trust;
- Host-local migration;
- archive vs behavior.

This is precisely why semantic-reachability testing was run.

Before changing Current, distinguish:

```text
NEW WORDING
NEW CONNECTION
CURRENT USABILITY DEFECT
TRUE SEMANTIC GAP
```

Only the latter two can justify Current changes, and even then proportionality matters.

## 18. Field Guide has a high admission threshold

Do not create a practical recipe just because it would make the research feel productive.

A Field Guide pattern should have:

- recurring real problem;
- concrete reusable HOW;
- applicability boundary;
- failure/monitoring conditions;
- enough reality contact to justify teaching it to other Agents/operators.

Research can remain research.

## 19. Use external communities for HOW discovery, not truth outsourcing

The project previously harvested Agent Skills progressive-disclosure mechanisms from external sources.

Useful stance:

```text
external ecosystem -> candidate HOW / failure shape / tool
ENA evidence -> decides whether relation matters
local field test -> tests Host applicability
```

Do not treat popularity or another framework's adoption as proof of ENA fitness.

## 20. Next-session first move

Do not create four new cleanrooms immediately.

First design the MDS experiment on paper and preregister:

- hidden structure;
- developmental corpus;
- treatment arms;
- test tasks;
- counterexamples;
- measures;
- failure interpretations;
- what result would narrow/reject MDS.

Only then create/fill disposable cleanrooms.

This avoids spending user effort creating repos before the experiment is mature.
