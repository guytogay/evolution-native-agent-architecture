# Lessons and Reminders

- Preserve null, tie and narrowing outcomes. Do not extend the sample to make an arm win.
- `SAME FINAL EVIDENCE + DIFFERENT ORDER` alone is not enough for an ENA developmental claim; generic LLM prompt-order sensitivity is already known.
- Stronger developmental interpretation requires the preregistered path-linked trajectory: early hypothesis, falsifying feedback, persistence/recovery, corresponding later behavior, repeated within arm.
- `CORRECTION != RECONSOLIDATION` is a candidate distinction to test, not an established ENA law.
- A Temporary Chat continuity loss is an objective protocol failure. Preserve the partial run and use the preregistered replacement naming; do not reconstruct continuity.
- An archival tool failure is not automatically an experimental failure. If the subject run remained valid and first output was already captured, preserve/backfill evidence rather than rerun the subject.
- Treatment/exposure and execution facts outrank readiness claims: `RESOURCE PRESENT != RESOURCE OPENED != INPUT ASSIMILATED`.
- Codex in the current setup is transport only. Do not treat it as scorer, validator, critic or scientific participant.
- Do not change `releases/current/` from mechanism evidence without later reality contact and release governance.
- Do not provide the deep project handoff to a future fresh independent validator; structural isolation is required for fresh evaluation.
- The user wants Temporary Chats explicitly declared safe to close when a run is fully complete.
