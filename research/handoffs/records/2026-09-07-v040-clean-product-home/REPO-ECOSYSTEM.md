# Repository Ecosystem

## `guytogay/ENA`
Role: clean product home for the next ENA.

State: `ACTIVE_DEVELOPMENT / NOT_CURRENT / NOT_PROMOTED`.

Keep this repository product-facing. Do not import legacy handoffs, project-management machinery, research tree shape, or Field Guide separation merely for continuity.

## `guytogay/evolution-native-agent-architecture`
Role: legacy architecture repository, v0.3.14 Current identity/package, research, experiments, evidence, historical occurrences, falsification, provenance, and maintainer succession records.

This repository remains the Current source until a successor is formally promoted. It is no longer the preferred product-development root for the next ENA.

## `guytogay/ena-field-guide`
Role: sunset historical practical-HOW experiment.

Do not continue it as a parallel product. Preserve/recover unique useful material, especially PR #6, then archive. Any practical HOW brought forward must earn inclusion in `guytogay/ENA` by real product value, not by old repo ownership.

## `guytogay/human-ai-workbench`
Role: canonical home for reusable human-AI project-working method, including continuation, handoff, coordination reduction, and related project-general practices.

These methods may be used by ENA maintainers without becoming ENA product content.

## `independent-validation-cleanroom*`
Role: disposable isolated execution surfaces.

Not product repositories and not canonical knowledge archives.
