# ENA Reconstruction — Degradation / Ablation Audit

Date: 2026-08-26

Status: `RESEARCH_AUDIT / ANTI_ABLATION / NOT_CURRENT`

Related: #80, #89–#94, PR #82, `MECHANISM-RETENTION-LEDGER.md`.

Purpose:

> Detect cases where reconciliation, semantic compression, stop rules, or `Host organ` classification may have preserved abstract correctness while losing concrete implementation value.

Audit verdicts:

- `SAFE_COMPRESSION` — semantic surface shrank while concrete HOW remained available.
- `SAFE_STOP` — architecture iteration stopped, but usable artifact/organ and reopen condition remain.
- `JUSTIFIED_SPECIALIZATION` — organ narrowed to a Host/problem family without losing the shared property.
- `REPLACED_WITH_PARITY` — old mechanism removed only after equivalent function was demonstrated.
- `UNRESOLVED_DEGRADATION_RISK` — concrete problem is remembered but implementation route is still weak/absent.
- `DEGRADATION` — a concrete useful mechanism disappeared or became materially less usable without parity evidence.

## DA-001 — Memory Metabolism semantic downgrade

**Transition**

`NEW_REFERENCE_SEMANTIC_CANDIDATE`

->

`REFERENCE_RECOMPOSITION / SEMANTIC_INTEGRATION_CANDIDATE / NOT_NEW_CAPABILITY`

**Audit**

The semantic novelty claim was narrowed after Current archaeology showed that memory class isolation, canonical-history/derived-knowledge separation, pruning/archive, contextual projection, durable read, and persistent state already existed.

However, the implementation route was not removed. The research branch still preserves:

- six reference memory layers;
- Memory Set / Cold Provenance Set / Decision Projection;
- provenance indirection;
- supersession/non-resurrection;
- authority separation;
- revalidation-before-material-use;
- contradiction handling;
- 24 deterministic selftest families;
- explicit relationship back to Current.

**Verdict**

`SAFE_COMPRESSION`

**Guard**

Do not later reinterpret `NOT_NEW_CAPABILITY` as `NO_REFERENCE_ORGAN_NEEDED`.

## DA-004 — Tiny Hot Kernel / Semantic Router described as Host organ

**Transition risk**

Current already contains Hot Cues + Cold Capability; implementation could be dismissed as Host-specific.

**Audit**

The property is semantically covered, but the practical questions are not resolved by prose:

- which resident recognizer phenotype notices relevant decision shapes economically;
- how to route from interrupt to exact cold Current semantics;
- what honest fallback looks like when retrieval is broken;
- how much context pressure each organ creates.

Three kernels, one router, blind fixtures, scorer, layered packet builder, and oracle-review protocol now exist.

**Verdict**

`UNRESOLVED_DEGRADATION_RISK` until controlled selection + Host mapping establish which implementation guidance deserves retention.

**Reason**

Prematurely demoting the whole area to `Host detail` would erase the practical adoption problem that motivated reconstruction.

## DA-005 — Effect Lifecycle as “already implied by rollback semantics”

**Transition risk**

Current already states distinctions such as local recovery vs external consequence.

**Audit**

A concrete Host still needs to decide after timeout/recovery/fork:

- retry same intent;
- query settlement;
- wait/backoff;
- compensate with a new effect;
- stop because the world already committed;
- reconcile manually when settlement is unknown.

The Intent / Attempt / Receipt / Commitment reference prototype and deterministic fixtures preserve this route.

**Verdict**

`SAFE_COMPRESSION_SO_FAR / INDEPENDENT_SELECTION_PENDING`

**Guard**

Do not delete or merge the four subjects solely because one higher-level Constitution sentence can describe the failure abstractly.

## DA-006 — Contested Authorship recovered but not yet machine-realized

**Transition risk**

Historical self-authorship research was often interpretable as agency/identity semantics already covered by Current.

**Recovered HOW**

Bounded self-surface; before/diff; proposer/provenance; counterpart readback where material; trial; reality contact; durable integration; disagreement/fork; authority separation.

**Gap**

The HOW currently exists primarily as a reconstruction/reference protocol, without the same fixture/validator depth as Memory Metabolism or Effect Lifecycle.

**Verdict**

`UNRESOLVED_DEGRADATION_RISK`

**Next evidence needed**

Concrete self-change fixtures + at least two Host mappings demonstrating that the protocol changes durable-change decisions without forcing ordinary memory/config edits through constitutional ceremony.

## DA-007 — Evidence Dependency Map

**Transition risk**

`N agents agree != N independent supports` is already semantically known, so dependency representation could be dismissed as metadata detail.

**Recovered HOW**

Represent model/prompt/source/tool/Host/witness common causes instead of counting agreeing outputs.

**Gap**

No durable machine prototype yet demonstrates the difference between apparent multiplicity and effective independent support.

**Verdict**

`UNRESOLVED_DEGRADATION_RISK`

**Next evidence needed**

Fixture showing:

- 5 reports from one shared source family != 5 independent supports;
- transformed/imported reports preserve dependency edges;
- genuinely independent evidence can remain independent even when stored in one repository.

## DA-008 — Generic Evidence Envelope

**Transition risk**

Evidence Applicability, Projection, Witness Survivability, Activation Witness, provenance, and support scope were historically spread across multiple research lines and later often labeled `covered/reference`.

**Recovered HOW hypothesis**

One reusable envelope carrying subject/applicability/provenance/witness/dependency/observation scope without claiming authenticity merely from representation.

**Gap**

The reconstruction has a reference design direction but not yet a small machine-guarded organ proving that reuse reduces duplicate machinery without becoming a giant universal evidence schema.

**Verdict**

`HIGH UNRESOLVED_DEGRADATION_RISK`

**Why high**

This cluster is exactly where earlier concrete tools can disappear into broad phrases such as `evidence discipline` or `scoped trust`.

**Next action**

Build the smallest reusable Evidence Envelope prototype with positive/negative fixtures and explicit optionality. Do not attempt to encode every evidence concept in ENA.

## DA-009 — Witness Survivability / Activation Witness / Distributed History Merge

**Transition risk**

These mechanisms are restored in #89 archaeology but currently live mainly as names inside the broader #94 workstream.

**Gap**

A future Generic Evidence Envelope could accidentally absorb the vocabulary while omitting the mechanisms:

- evidence must sometimes survive the same failure domain as the actor/state it witnesses;
- activation/execution claims require evidence of actual activation/effect, not merely configuration presence;
- distributed histories need merge/reconciliation semantics rather than last-writer narrative overwrite.

**Verdict**

`UNRESOLVED_DEGRADATION_RISK`

**Guard**

When building Evidence Envelope, preserve these as separately testable behaviors even if they reuse one envelope structure.

## DA-010 — LITE adoption / finite-context adoption economics

**Transition risk**

Historical LITE adoption and runtime-kernel work is restored to the archaeology map, but there is still a tendency to treat `complete adoption baseline` as a documentation concept rather than a usable finite-context implementation problem.

**Current recovery path**

Tiny Hot Kernel + Semantic Router partially realizes the runtime side of LITE adoption.

**Gap**

No complete reference adoption packet yet demonstrates:

`minimal resident kernel + exact Current identity + cold source + router/fallback + local Host mapping + refresh/invalidation`.

**Verdict**

`UNRESOLVED_DEGRADATION_RISK`

**Next evidence needed**

A compact end-to-end Local Projection/adoption reference packet on at least one real Host, with measurable resident cost and refresh behavior.

---

# Audit conclusion

No confirmed recent **hard degradation** was found in the already-prototyped Memory Metabolism / Retrieval / Projection / Effect Lifecycle surfaces.

The more dangerous pattern is different:

> **historical concrete mechanisms have been restored to the research map, but several remain one abstraction step away from disappearing again because their HOW has not yet been rebuilt into an executable/reference organ.**

Highest-priority anti-degradation surfaces after this audit:

1. Generic Evidence Envelope, while preserving Witness Survivability / Activation Witness / dependency structure as separately testable behaviors;
2. Evidence Dependency Map;
3. Contested Authorship fixtures/Host mapping;
4. end-to-end LITE adoption packet after Tiny Kernel selection evidence.
