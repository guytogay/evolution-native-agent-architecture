# ENA Research — Start Here

Use this page only when you need a research-oriented entrypoint. The live project state is `../NOW.md`.

## Normal continuation

1. Read `../NOW.md`.
2. Read the Issue/artifact directly relevant to the next consequential action.
3. Verify Current from `../releases/current/CURRENT-BASELINE.yaml` only when the decision depends on Current identity.
4. Retrieve deeper methodology/history only if it can change the decision.
5. Start useful work when the goal, known state, uncertainty, and next action are clear.

Do not perform a full repository audit by default.

## When deeper context is justified

Retrieve old handoff, progress, reconciliation, branch, candidate, freeze, or release material when you are actually answering questions about:

- historical lineage or why a decision was made;
- released/candidate identity;
- high-consequence authority/recovery changes;
- an old failure/counterexample likely to be repeated;
- an independent-validation boundary where prior context would contaminate the evidence.

Otherwise, leave it cold.

## Current research focus


## Working rule

For ordinary research/doc changes outside Current, normal Git diff + relevant review is enough. Do not regenerate handoff packages, reconciliation records, release proofs, or package readbacks merely because a research sentence changed.

Executable logic still deserves executable tests; release identity still deserves release-level validation.
