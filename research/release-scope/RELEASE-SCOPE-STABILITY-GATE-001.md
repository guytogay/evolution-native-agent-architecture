## Reopen conditions

Reopen release scope when candidate assembly or new evidence shows, for example:

- a selected cargo class cannot be implemented without duplicating/contradicting Core semantics;
- optional-reference packaging creates unavoidable mandatory behavior;
- language/accessibility requirements force a materially different package surface;
- an unselected HOW becomes candidate-critical through a concrete failure;
- a real semantic contradiction requires changing the v0.3.6 trunk rather than adding operational guidance;
- independent candidate falsification finds a scope-level, not merely implementation-level, defect.

Otherwise the next step is **version selection followed by candidate-build preparation**, not more scope ideation.
