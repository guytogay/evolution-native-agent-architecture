# ENA Operational Architecture Assembly

Status: `ASSEMBLY_WORKSPACE / RESEARCH_ONLY / NOT_CURRENT / NOT_RELEASE_AUTHORITY`

This directory is the assembly surface between ENA's stable semantic trunk and the plural concrete mechanisms an Agent/Host can actually use.

It exists because:

```text

!=

```

and because the opposite mistake is also possible:

```text

!=
traversable architecture
```

## Node shape

A useful assembly node should normally expose:

```text
WHAT / WHY
    |
    +--> HOW-A
    |      +--> applicability / trigger
    |      +--> concrete procedure / state / tool / adapter
    |      +--> failure / fallback / WAIT / REFUSE
    |      +--> Host mappings
    |      +--> evidence / residuals
    |
    +--> HOW-B
    +--> dormant / experimental HOWs
    |
    +--> composition links to other nodes
```

No fixed checklist is mandatory if a different shape is more useful. The test is whether a fresh Agent can find a concrete action path or an honest named gap.

## Assembly rules

1. **Preserve plurality.** Do not collapse materially different HOWs merely because they satisfy one property.
2. **Reuse before proliferating.** A new seam may be solved by composing existing organs rather than creating a new subsystem.
3. **Keep Host applicability explicit.** A mature Host-native HOW does not become universal ENA machinery.
4. **Keep evidence scoped.** Machine consistency, external mechanism existence, Host field evidence, and ecological evidence are different claims.
5. **Keep residuals visible.** UNKNOWN, WAIT, dormancy, manual procedure, and non-transferability are valid outcomes.
6. **Keep history recoverable.** Retired/failed HOWs may leave the active map, but their lineage is not erased.
7. **Do not solve context cost by deleting architecture.** Repository richness and active runtime context are separate problems.
8. **Do not solve runtime routing by loading everything.** Tiny Hot Kernel / semantic routing should locate relevant branches.
9. **Do not rewrite Current during assembly.** Release-scope reconciliation is a later phase.
10. **Route by consequence before ceremony.** Clearly non-material local work should not automatically trigger full authority/effect/settlement machinery; material or unknown consequences route upward.

## Evidence labels in the map

The map uses prose evidence descriptions instead of one universal maturity score. Typical evidence classes include:

- deterministic/static counterexample;
- research prototype machine checks;
- external mature engineering mechanism;
- real Host observation;
- independent validation;
- naturalistic field evidence;
- ecology/mesocosm evidence;
- unresolved / not yet observed.

These labels are descriptive, not a mandatory ladder.
