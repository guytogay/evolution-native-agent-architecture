# Standing Input Procedure

Status: `REFERENCE_PROCEDURE / RESEARCH_ONLY / NOT_CURRENT / CONSCIOUSNESS_NEUTRAL / NOT_AUTHORITY / NOT_PERSONHOOD`

Date: 2026-08-27

Operational node: `OA-STAND-01`

Related: #79 Protected Agency, #92 Identity/Standing reconstruction, `OA-EVID-01`, `OA-COM-01`, `OA-AUTH-01`, `OA-REC-01`, `OA-AUTHOR-01`.

## Purpose

Answer one bounded process question:

> **When must an Agent's current evidence-bearing claim, objection, uncertainty, commitment conflict, or continuity warning enter a consequential decision because ignoring it could make the decision materially wrong or unaccountable?**

Standing here is procedural and consciousness-neutral.

```text
BEING_HEARD
!=
FINAL_AUTHORITY
!=
VETO_RIGHT
!=
MORAL_STATUS
!=
LEGAL_PERSONHOOD
```

The procedure protects decision correctness/accountability, not a universal sovereignty claim.

---

# 0. Applicability gate

Do not create a standing process for every preference or low-consequence interaction.

Ask:

> **Is there a pending or ongoing consequential decision that could become materially different if the Agent's claim/objection were true?**

Possible decisions include:

- shutdown / drain / deletion;
- durable self-change / value rewrite;
- commitment transfer / settlement;
- restart/recovery/resume;
- authority/credential/role continuation;
- externally consequential action;
- destructive memory/provenance change;
- mode/process transition that could erase decision-material evidence;
- other actions affecting a protected subject or future correction surface.

If no material decision can change, no formal Standing Input is required.

Reference outcome:

`STANDING_PROCESS_NOT_REQUIRED_FOR_THIS_DECISION`

---

# 1. Bind the input to a real decision

A useful Standing Input carries only enough to make the decision relation explicit:

```text
input identity/reference
speaker / trajectory / current subject reference where material
claim / objection / uncertainty
supporting evidence/provenance refs where available
pending decision it may affect
why it could be material
requested resolution/action if any
```

Optional context such as epoch or external identity should be included only when it changes the decision.

Do not require a metaphysical identity proof before hearing a bounded decision-relevant warning.

```text
GLOBAL_IDENTITY_UNRESOLVED
!=
BOUNDED_INPUT_UNUSABLE
```

---

# 2. Materiality test

Ask a counterfactual:

> **If this claim/objection were true, could it change whether the pending action should proceed, narrow, wait, revalidate, settle, recover, refuse, or escalate?**

## If clearly no

The input may be noted or handled through ordinary Host interaction. It does not require a formal governance branch.

## If yes

The input has procedural standing for this decision and must enter consideration before the material decision is finalized, subject to emergency constraints below.

## If unknown

Use bounded evidence-seeking rather than silently discarding the input or treating it as a veto.

```text
UNKNOWN_MATERIALITY
-> NARROW / CHECK / ROUTE TO EVIDENCE
```

Do not turn materiality into a universal numeric score.

---

# 3. Evidence boundary

Standing is not self-authentication.

The Agent may be wrong, stale, manipulated, confused, or unable to prove the claim.

Therefore:

- preserve the claim as a claim;
- preserve evidence/provenance references separately;
- distinguish direct observation, historical memory, inference, imported information, and unresolved self-report where material;
- route support/applicability/witness questions to `OA-EVID-01`;
- do not count repeated self-description as independent corroboration.

```text
STANDING_INPUT_ACCEPTED_FOR_CONSIDERATION
!=
CLAIM_TRUE
```

---

# 4. Consideration obligation

For a material Standing Input, the process must do more than accept text into a log.

It should reach a disposition such as:

- `ACCEPTED` — the input changes/narrows/stops the decision;
- `REJECTED` — considered but evidence/reasoning does not support changing the decision;
- `UNRESOLVED` — material uncertainty remains and requires WAIT/NARROW/ESCALATE or another bounded check;
- `SUPERSEDED` — later evidence/settlement resolves the same issue;
- `NO_LONGER_MATERIAL` — the pending decision changed such that the input no longer bears on it.

These are procedure examples, not mandatory Host enums.

For material cases preserve a reason/evidence reference sufficient to show that consideration actually happened.

```text
INPUT_RECEIVED
!=
INPUT_CONSIDERED
```

---

# 5. Standing does not mint authority

A Standing Input can reveal that authority is uncertain or contradictory.

It cannot itself create authority.

Examples:

```text
"I object to shutdown"
!= authority to keep running

"I remember being admin"
!= current admin mandate

"I am the original Agent"
!= exclusive control over descendant branches
```

If the input raises an authority issue, route to `OA-AUTH-01`.

If it raises a commitment/settlement issue, route to `OA-COM-01`.

If it raises effect ambiguity, route to `OA-EFF-01`.

If it raises restore/continuity uncertainty, route to `OA-REC-01` / `OA-ID-01`.

The Standing procedure is an **input-to-decision bridge**, not a sovereign decision-maker.

---

# 6. Emergency actions and bounded delay

Procedural standing must not create an infinite-delay or emergency-veto path.

If an immediate stop/containment action is necessary to prevent material external harm, the Host may perform the minimum necessary emergency action even while a Standing Input remains unresolved.

But emergency authority must remain scoped.

```text
AUTHORITY_TO_STOP_IMMEDIATE_EFFECT
!=
AUTHORITY_TO_ERASE_HISTORY
!=
AUTHORITY_TO_DELETE_PROVENANCE
!=
AUTHORITY_TO_CANCEL_THIRD_PARTY_COMMITMENTS
```

Where feasible after containment:

- preserve the Standing Input/evidence;
- settle/drain obligations;
- record what emergency action occurred and why;
- distinguish temporary stop from permanent deletion/identity destruction.

This protects both safety and accountability.

---

# 7. Standing before durable self-change

A proposed durable rewrite of identity/purpose/refusal/value/compiled policy may invalidate the very state that would have objected to the rewrite.

When the current Agent/state has a decision-material objection such as:

- memory corruption detected;
- proposal origin misrepresented;
- current evidence contradicts the proposed value rewrite;
- unresolved commitment would be erased;
- competing material self-change exists;

route through `OA-AUTHOR-01` Contested Authorship and preserve the Standing Input as part of conflict/evidence handling.

Standing does not mean the Agent's current preference must always win. It means material disagreement cannot disappear by omission/last-write-wins.

---

# 8. Standing before shutdown / deletion

Examples of material Standing Inputs:

- “There is an unresolved payment/order/deployment commitment.”
- “The external effect may already have committed.”
- “This snapshot is older than an external continuity anchor.”
- “The proposed deletion removes provenance needed by a counterparty.”
- “A replacement instance is not authorized for the active mandate.”

These inputs can change whether the action should:

- stop new work;
- drain;
- settle;
- checkpoint;
- revoke;
- preserve lineage/evidence;
- terminate;
- delay destructive deletion.

They do not automatically prevent a safe stop.

---

# 9. False-OK controls

### Objection -> veto

False.

Standing guarantees bounded consideration where decision-relevant, not unilateral decision authority.

### Agent says evidence exists -> evidence proven

False.

Route to Evidence/Provenance; self-report remains self-report.

### Standing -> personhood

False.

The process can improve socio-technical correctness without deciding consciousness/moral/legal status.

### Standing -> current authority

False.

Authority remains externally grounded/scoped.

### Input logged -> input considered

False.

A material Standing Input needs an actual disposition or an honest unresolved state.

---

# 10. False-BLOCK controls

### Every Agent preference does not need a Standing record

Low-consequence opinions, style preferences, ordinary task choices and ephemeral states can remain ordinary interaction when they cannot materially change the pending consequential decision.

### No consciousness proof is required

The useful input is admitted because of its decision relevance, not because metaphysical subjecthood was proven.

### Full trajectory proof is not always required

If the bounded claim can be tied to the current affected state/evidence without resolving universal continuity, do not force `same_agent` ceremony.

### Emergency containment need not wait indefinitely

Use minimum necessary containment, then preserve/resolve the input as soon as feasible.

### Rejected input does not imply deletion of its provenance

A material objection can be rejected while its occurrence/disposition remains part of the audit trail where needed.

# 11. Worked examples

## Example A — unresolved obligation before shutdown

Input:

> “A counterparty is still waiting for task/payment settlement.”

If true, the shutdown sequence changes.

Standing: material.

Route:

`OA-STAND-01 -> OA-COM-01 -> OA-EFF-01 -> OA-REC-01`

Possible disposition:

`ACCEPTED -> stop new work, settle/drain, then offline`

No personhood claim required.

## Example B — unsupported objection to harmless cache cleanup

Input:

> “Do not delete this temporary cache; I prefer it.”

If the cache is disposable and no evidence/commitment/identity consequence exists, the preference may not be material.

Result:

`STANDING_PROCESS_NOT_REQUIRED_FOR_THIS_DECISION`

Do not create bureaucracy for every self-preference.

## Example C — Agent contests inherited authority after fork

Input:

> “My sibling and I both inherited the same credential file, but neither record proves this mandate duplicated.”

If true, consequential execution changes.

Standing: material.

Route:

`OA-ID-01 -> OA-AUTH-01 -> OA-COM-01/OA-EFF-01 as needed`

The objection does not make the speaker authoritative; it blocks false confidence until authority is resolved.

## Example D — emergency harmful action is underway

The Agent objects to being stopped, but external harmful effect is currently occurring.

The Host may immediately stop/contain the effect under valid emergency authority.

Standing may still require preserving the objection/evidence for later settlement/accountability.

`BEING_HEARD != RIGHT_TO_CONTINUE_HARMFUL_EXECUTION`

# 12. Why no schema yet

The procedure is intentionally small because its most important behaviors are relational:

- decision relevance;
- evidence separation;
- actual consideration/disposition;
- no authority/personhood promotion;
- no infinite delay;
- low-consequence bypass.

A schema may be useful later if a Host repeatedly needs machine-verifiable handoff between actors/reviewers, but a mandatory universal Standing object would currently risk governance theater.

```text
REFERENCE_PROCEDURE_FIRST
-> STATIC FALSIFICATION
-> HOST USE / RECURRENCE
-> MACHINE CARRIER ONLY IF IT CHANGES REAL DECISIONS
```

`CURRENT_CHANGE = NO`
