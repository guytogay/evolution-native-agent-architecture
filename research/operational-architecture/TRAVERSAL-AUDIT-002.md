## Finding A — the thin entry layer is useful

The cue index changes the navigation shape from:

```text
ordinary problem
-> scan long map / know ENA vocabulary
-> node
```

into:

```text
ordinary problem
-> compact failure/cue family
-> one or more nodes
-> concrete HOW branch
```

This is a meaningful assembly improvement because it separates **recognition/routing** from **full mechanism content**.

## Finding B — many-to-many routing survived

The index did not force one cue into one classifier label.

Examples:

```text
restore+retry
-> Recovery + Effect + Settlement + Authority

fork+promise
-> Commitment + Identity + Authority + Effect
```

This is important because composition seams are often where false confidence appears.

## Finding C — consequence-first routing repairs a historical Host failure class

The first audit found harmless/local work was under-routed by the map: the ingredients existed, but no thin entry cue prevented over-application of high-assurance machinery.

The pre-router now gives a non-numeric qualitative fork:

```text
clearly non-material local action
-> lightweight Host-native path

material action
-> relevant operational branches

unknown consequence
-> narrow / inspect / route upward
```

This does not create a blanket exemption for local actions and does not infer safety from ignorance.

## Finding D — the next bottleneck moves deeper

After cue discoverability is repaired statically, the next repeated question becomes:

> Once I reach a HOW, can I find the exact procedure/tool/prototype/Host adapter needed to instantiate it?

Current map depth is uneven.

Examples with relatively concrete implementation relatives:

- idempotency / fencing / optimistic concurrency / durable workflow;
- Retrieval Obligation;
- Commitment/Settlement reconstruction;
- migration-settlement composition;
- lineage compaction;
- evidence/provenance external relatives.

Examples still more procedure/policy/evidence-open:

- rehabilitation policy;
- Standing Input implementation shape;
- role/control retirement;
- selective legibility Host binding;
- language cold-path completion;
- verification-as-service ecology.

This asymmetry should remain visible.

## Finding E — do not jump directly to a machine router schema

The static cue index is useful, but we have not yet established:

- which cues should be always hot;
- which cues are naturally recognized by fresh Agents;
- which cue aliases differ by Host/language;
- whether exact keyword, semantic retrieval, or Host-native hooks route best;
- whether a machine schema would reduce or increase maintenance drift.

Therefore:
