# 9. Evolution Metabolism and Ecology — Current

Status: `CURRENT / FIELD_VALIDATION`

The retained model is:

`environment/stimulus -> mutation pressure -> variation -> latent/expression -> reality contact -> local selection -> retention/dormancy/loss -> migration/recombination -> renewed variation`

Core distinctions:

`stimulus != mutation != improvement`

`stored != expressed != applied != selected`

`local selection != universal fitness`

`publication != receiver adoption`

Variations may remain latent without immediate experiment or verdict. Consequential experiments use a suitable Variation Space. Lifecycle, expression, and evidence-backed selection are separate axes.

Migration transfers a possibility plus represented source history, not a local conclusion. Packet digest does not authenticate source. Composition may degrade, cancel, add, amplify or create emergence; observe the combined subject where interaction matters.

Self-affecting mutation that can disable recovery should keep an external/reachable rescue path when consequence warrants it. Restore success does not imply external rollback or restored authority.

Control retirement requires original-purpose/replacement/coverage evidence and reactivation lineage; `NO_INCIDENT != CONTROL_NOT_NEEDED`.

## Minimum operating loop

ENA evolution is not complete merely because the lifecycle above is understood. A Host that intends durable self-evolution needs an executable loop, even if the concrete organs are Host-native.

```text
signal / idea / correction / failure / success
-> durable inbox or candidate queue
-> candidate hypothesis + proposed change
-> LATENT by default
-> decide whether real trial can change a decision
-> decision-relevant baseline + recovery/authority boundary when material
-> bounded expression / Variation Space / real task
-> observe outcomes before interpretation
-> local selection: SUPPORTED | PARTIAL | NOT_SUPPORTED | HARMFUL | UNKNOWN
-> integrate / retain / adapt / dormant / reject / archive
-> wake again on relevant signal or environment change
```

Canonical operating HOW: `operational/procedures/EVOLUTION-LOOP.md`.

A useful minimum Host implementation should be able to identify or explicitly mark absent, when applicable:

- durable signal/inbox capture;
- latent candidate storage distinct from active self;
- a real bounded variation/trial surface;
- before/after evidence or baseline relevant to the hypothesis;
- recovery when self-disable risk makes it material;
- a selection record that preserves negative/unknown outcomes;
- a wake/review mechanism for relevant latent material.

These functions do not require seven separate tools. A Git repository, issue queue, JSONL ledger, database, task memory, experiment runner, cron/event hook, snapshot/watchdog or other Host-native mechanism may implement one or several of them.

```text
EVOLUTION_VOCABULARY != EXECUTABLE_EVOLUTION_LOOP
PROTECTION_OF_EVOLVABILITY != EVOLUTION_ITSELF
NO_NEW_SIGNAL != FAILURE_TO_EVOLVE
EVOLUTION_LOOP != CONTINUOUS_SELF_EDITING
```

`tools/ena_evolve_v2.py` remains the narrow practical v2 record/packet path. It can create/import/export/validate candidate records and packets; it is **not** a full expression/trial/evaluation/integration lifecycle engine and cannot prove external truth. Hosts may use it where useful and implement the rest of the loop through native machinery.

> **Capture pressure, preserve variation, touch reality, select locally, retain the evidence, then observe again.**
