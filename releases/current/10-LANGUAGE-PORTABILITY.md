# 10. Language Portability and Semantic Projection — v0.3.9

Status: `CURRENT / FIELD_VALIDATION / OPERATIONAL_LANGUAGE_PROJECTION`

ENA must not depend on English proficiency to remain usable. A language version is a semantic projection of one release identity, not a second Constitution or machine implementation.

Two different parity questions must be kept explicit:

```text
DECISION_SEMANTIC_PARITY
!=
RELEASE_ADOPTION_IDENTITY_PARITY
```

Both are machine-checkable only in represented scope; neither fixture structure nor matching release labels prove future behavioral equivalence.

Stable IDs and decision meaning cross languages; literal wording need not.

High-risk distinctions include:

`capability != authority`; `stimulus != mutation != improvement`; `stored != expressed != applied != selected`; `local selection != universal fitness`; `bundled reference != required/default-active`; `cue match != applicability proven`; `being heard != sovereignty/authority`; `cancel != rollback != compensation`; `available resource != default hot payload`.

Decision-bearing zh-CN operational surfaces live under `language-projections/zh-CN/`. Canonical machine bytes remain shared under `references/`, `schemas/`, `templates/`, and `tools/`.

`language-projections/semantic-fixtures.v3.yaml` defines paired decision scenarios. The Current validator separately checks zh-CN source/release identity so a semantically reasonable translation cannot silently remain on an obsolete Current/candidate state.

```text
TRANSLATED != BEHAVIORALLY_EQUIVALENT
FIXTURE_DEFINED != MODEL_PASS
IDENTITY_LABEL_PRESENT != IDENTITY_PARITY_PROVEN
```

Language can be an applicability boundary when it changes a decision.

> **Translate wording; preserve decisions and release identity.**
