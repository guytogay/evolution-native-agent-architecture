# 9. 进化代谢 — v0.3.5 candidate.1 简体中文语义投影

本文件把“促进持续自我进化”变成可以运行的参考循环。它是参考机制，不要求所有 Host 照抄同一种器官。

## 9.1 进化代谢循环

`观察 → 唤醒 → 产生变异 → 实验 → 评估 → 选择 → 整合/淘汰 → 迁移/重组 → 再循环`

关键区别：

`变异 ≠ 改进`

`实验 ≠ 整合`

`生命周期状态 ≠ 基于证据的选择状态`

`来源结果 ≠ 接收方已经证明适用`

## 9.2 进化唤醒

事件触发可以来自用户纠正、重复失败/摩擦、矛盾、值得泛化的重复成功、能力/环境变化、新机会或适应陈旧。

还可以使用 Host 自己选择的周期/空闲复查作为补漏机制。

**定时器触发的是复查，不是强制修改。**

ENA 不规定统一的“每 7 天”或“每 10 次对话”。

## 9.3 变异空间（Variation Space）

变异空间回答：

> 还不知道这个变化好不好时，在哪里可以让它真实接触现实并产生学习，而不用事前证明它一定正确？

例如分支、沙箱、一次性虚机/容器、影子运行、小范围试运行、测试 Agent、可恢复本地配置、隔离 skill 版本、模拟/回放环境。

内部权限/能力拓扑也可以成为变异对象，但变异空间必须说明什么能变、谁承担后果、哪些效果会逃出空间、恢复/清理现实，以及哪些对外行为仍需要真实授权。

## 9.4 两条独立状态轴

candidate.1 不再用一个 `status` 同时表达“做到哪一步”和“证据怎么看它”。

生命周期状态：

`PROPOSED（已提出） | EXPERIMENTED（已实验） | INTEGRATED（已整合） | ARCHIVED（已归档） | RETIRED（已退役）`

选择状态：

`UNASSESSED（尚未评估） | SUPPORTED（支持） | PARTIAL（部分支持） | NOT_SUPPORTED（不支持） | HARMFUL（有害） | UNKNOWN（未知）`

因此：

- `INTEGRATED + UNKNOWN`：因为后果有边界而整合了一个仍未知的变异；整合没有把它证明成成功。
- `ARCHIVED + HARMFUL`：已经退出活跃集合，但“有害”这个选择事实仍然保留。
- `ARCHIVED + SUPPORTED`：曾经得到支持，但现在不再活跃；归档不改写历史选择结果。

## 9.5 评估和选择必须接触现实

重要结果按维度记录：

`IMPROVED（变好） | DEGRADED（变差） | UNCHANGED（没变） | UNKNOWN（未知）`

任何正式选择结论都必须先有至少一次被表示出来的实验。不能靠“我觉得”“别人说过”“迁移包写着成功”或“文件写成功了”直接制造 `SUPPORTED`。

`SUPPORTED / PARTIAL` 至少要有一个真实记录的改善维度和证据引用；`HARMFUL` 至少要有一个变差维度和证据引用。

参考工具只记录证据引用，不会因为你填了字符串就替你证明证据是真的。

## 9.6 整合

整合不同于实验，也不同于“已经证明变好”。

参考工具要求候选先有实验和当前明确评估。`SUPPORTED / PARTIAL` 可以在真实授权允许时整合；`UNKNOWN` 只有显式 `--allow-unknown` 才能有界整合，并继续保持 `selection_state=UNKNOWN`；负面或尚未评估的候选不能被当作保留适应整合。

提交式整合还要记录真实授权依据和恢复/不可逆边界。工具记录这些主张，但不证明它们真的成立。

`INTEGRATED ≠ SUPPORTED`

## 9.7 淘汰和整理

淘汰改变的是生命周期，不是选择结论。

一个有害候选归档以后仍然是有害证据；一个曾受支持但已经陈旧的适应归档以后仍保留当时的来源事实。

从活跃行为中移除某个适应，与删除历史/受监管数据，是两个不同决定。

## 9.8 迁移包与族群学习

迁移包在已表示的情况下保留：来源生命周期、来源选择状态、来源实验、来源评估、整合/归档/迁移谱系、来源环境、依赖、未知和内容摘要。

包的用途严格从**选择状态**推导，而不是从“已经整合/归档”这种生命周期推导：

`SUPPORTED/PARTIAL → ADAPTATION_CANDIDATE（正向适应候选）`

`NOT_SUPPORTED/HARMFUL → NEGATIVE_EVIDENCE（负面证据）`

`UNASSESSED/UNKNOWN → UNRESOLVED_VARIATION（尚未解决的变异）`

包内 digest（摘要）只检查内部一致性，**不是来源认证**。能改整个包的人也能重新计算 digest。

接收方导入后，本地选择状态重新从 `UNASSESSED` 开始，同时把来源选择和证据谱系单独保存。

`TRANSFERRED（已传播） ≠ LOCALLY_APPLICABLE（本地适用） ≠ LOCALLY_SELECTED（本地已选择）`

即使来源是 `HARMFUL / NOT_SUPPORTED`，接收方也可以因为环境不同而在自己的真实变异空间重新实验。如果本地现实出现不同结果，可以产生新的本地正向选择，但必须保留“来源曾经失败/有害”的谱系。

这允许族群加速进化，同时防止把迁移变成复制结论。

## 9.9 重组与涌现

组合可能冲突、抵消、线性改善、放大改善或涌现新能力。

正向涌现只有在真实观察到时才是证据；“我们期待会涌现”不是证据。

## 9.10 治理收敛

candidate.1 的 `closure` 参考工具会读取已经表示出来的进化状态和调用者输入。未复查信号、已经实验但仍 `UNASSESSED / UNKNOWN` 的候选，会形成显式证据义务，不会因为调用者没写 blocker 就消失。

参考结果：

`READY | NARROW_AND_PROCEED | EVIDENCE_NEEDED | STOP_OR_ESCALATE`

它的证据范围是 `REPRESENTED_STATE_AND_INPUTS_ONLY（只基于已表示状态和输入）`。

即使输出 `READY`，也不能证明现实世界不存在尚未表示的 blocker。

如果继续检查已经不可能改变决定，就停止增加治理，开始行动并观察。

## 9.11 参考工具

`tools/ena_evolve.py` 提供：

`init / observe / review / propose / experiment / evaluate / integrate / archive / export / import / closure / status / selftest`

candidate.1 还提供 `tools/candidate1_adversarial.py`，把第一版冻结候选经独立反证机械复现的问题变成回归测试。

参考工具不会自动修改任意 Host，不会证明外部证据真假，不会证明授权真实，不会证明恢复一定有效，也不会认证迁移包真正来自其声称的来源。

**机器写出的 JSON 不会因为“机器可读”就自动变成更强的现实真相。**

> **先允许变异，让现实选择。**
>
> **不要崇拜工具；继续改进它。**
