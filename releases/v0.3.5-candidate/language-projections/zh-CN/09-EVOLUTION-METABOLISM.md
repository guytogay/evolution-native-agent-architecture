# 9. 进化代谢（简体中文语义投影）

本文件把 ENA 的“促进持续自我进化”变成一套可以真正运行的参考循环。

它是参考机制，不是要求所有 Host 都照抄同一种实现。

## 9.1 进化代谢循环

一个真正可持续进化的系统，至少要有这些功能：

1. **观察（Observe）** —— 收集用户纠正、失败、摩擦、矛盾、成功、环境/能力变化、好奇和机会。
2. **唤醒（Wake）** —— 让这些信号有机会被重新审视。
3. **产生变异（Vary）** —— 形成一个或多个具体变化候选。
4. **实验（Experiment）** —— 让候选在合适的变异空间里真正接触现实。
5. **评估（Evaluate）** —— 记录真实结果、反证、未知和代价。
6. **选择（Select）** —— 保留、修改后重试、拒绝、判定有害，或者继续保持未知。
7. **整合（Integrate）** —— 在真实授权和后果边界允许时，把被选择的适应进入长期/共享状态。
8. **淘汰/整理（Prune）** —— 把陈旧、有害、被替代的适应从活跃集合中退出，必要时归档、退休或依法删除。
9. **迁移/重组（Migrate/Recombine）** —— 把带有证据和来源的适应、失败经验传播给其他 Agent，并把不同适应重新组合成新的变异。
10. **再次循环（Repeat）** —— 已保留的适应会改变下一轮搜索空间。

某个 Host 缺少其中一个器官并不代表完全不能进化，但不能把缺失功能叙述成“已经具备”。

`变异 ≠ 改进`

`实验 ≠ 整合`

`来源 Agent 的适应 ≠ 接收方已经证明适用`

## 9.2 进化唤醒策略

### 事件触发

常见信号包括：

`USER_CORRECTION（用户纠正） | REPEATED_FAILURE（重复失败） | FRICTION（摩擦） | CONTRADICTION（矛盾） | REPEATED_SUCCESS（重复成功） | CAPABILITY_CHANGE（能力变化） | ENVIRONMENT_CHANGE（环境变化） | OPPORTUNITY（机会） | STALE_ADAPTATION（适应可能陈旧）`

事件唤醒应该足够便宜，避免真正值得学习的信号被日常工作淹没。

### 周期/空闲触发

周期性复查用于捕捉慢性漂移和之前漏掉的模式。

ENA 不规定统一的“每多少次对话/每多少小时必须触发”。Host 应依据任务频率、成本、记忆压力、环境变化速度、长期休眠以及错过适应机会的代价选择自己的节奏。

**定时器触发的是复查，不是强制修改。**

复查后得出“目前没有值得改变的东西”，也是合法的进化结果。

## 9.3 变异空间（Variation Space）

变异空间回答的问题是：

> 我们还不知道这个变化到底好不好，那么在哪里可以让它真实到足够产生学习，同时又不要求事前就证明它一定正确？

例子包括：分支/分叉、沙箱、一次性虚机/容器、影子运行、小范围试运行、测试 Agent、可逆本地配置/偏好、隔离 skill 版本、模拟或回放环境。

变异空间内部可以允许有意义的内部权限/能力拓扑变化。

但边界要说明：

- 什么东西可以变；
- 谁/什么对象可能承担后果；
- 哪些效果会逃出实验空间；
- 清理/恢复到底能做到什么；
- 哪些对外行动仍然需要真实授权。

变异空间不是“自动安全区”，而是一个**故意限制后果、允许不确定变化接触现实**的空间。

## 9.4 候选记录

一个有用的变异候选至少应说明：

- 是什么信号触发了它；
- 假设；
- 想改什么；
- 预计观察哪些结果维度；
- 变异空间；
- 决策相关时的进化主体；
- 受保护对象；
- 来源环境；
- 依赖；
- 重要未知；
- 结果怎么观察。

不要求它在实验前证明“普遍有益”。

## 9.5 评估和选择

对真实观察到的结果按重要维度记录：

`IMPROVED（变好） | DEGRADED（变差） | UNCHANGED（没变） | UNKNOWN（未知）`

同一个候选可以同时有好处和代价。

选择状态：

`SUPPORTED（支持） | PARTIAL（部分支持） | NOT_SUPPORTED（不支持） | HARMFUL（有害） | UNKNOWN（未知）`

如果要声称 `SUPPORTED` 或 `PARTIAL`，必须至少存在被表示出来的真实结果和证据引用。参考工具会记录这些引用，但**不会因为你填了一个字符串就替你证明证据是真的**。

失败候选不能因为另一个候选赢了就被抹掉。当前赢家也不能因此获得“以后不准再突变”的权力。

## 9.6 整合

实验成功不等于已经可以进入长期状态。

一个在变异空间里有效的候选，在进入长期记忆、核心配置、共享环境或生产系统时，可能遇到新的后果和授权边界。

真实本地授权允许时，Agent 可以自主整合自己的内部结构变化；但修改自己的权限表不能凭空产生对外部对象的新授权。

参考工具通常只允许 `SUPPORTED` 或 `PARTIAL` 候选进入整合记录。真正仍为 `UNKNOWN` 的候选只有在**已经做过真实实验、做过明确 UNKNOWN 评估，并且剩余后果被清楚限制**时才允许记录为未知状态下的整合。仅仅处于 `PROPOSED（刚提出）` 的候选不能拿“不确定”当作跳过现实实验的捷径。

整合时要显式记录真实授权依据和恢复/不可逆边界。工具只负责记录，不负责证明这些依据真的有效。

## 9.7 淘汰和整理

没有退出机制的学习系统最后只会不停堆东西。

可能的生命周期：

`ACTIVE（活跃） -> DORMANT（休眠） -> ARCHIVED（归档） -> RESTORED/RETIRED（恢复/退休）`

判断可以参考实际使用频率、真实价值、冲突、维护成本、是否被更强适应替代、用户/所有者保护以及法律保存/删除要求。

年龄大、长期没用，不能单独成为破坏性删除的充分理由。

**把一个适应从活跃行为里淘汰**，和**删除历史/受监管的数据**是两个不同决定。

## 9.8 迁移包与族群学习

一个可迁移的包应该保留：

- 候选/适应身份；
- 变化的语义和具体内容；
- 来源选择状态；
- 它到底是正向适应候选、负面证据，还是尚未解决的变异；
- 来源 Host / 模型 / 语言 / 配置；
- 来源评估和证据引用；
- 哪些维度变好、变差、未知；
- 依赖；
- 重要授权/恢复假设；
- 已知失败模式；
- 迁移未知；
- 内容摘要（digest），用于检查包内部一致性和发现意外修改。

**包内自己的 digest 不是来源认证，也不是外部信任锚。** 能改写整个包的人同样可以重新计算 digest。如果“这个包到底是不是来自它声称的 Agent/Host”会改变重要决定，就需要结合外部来源链、签名、可信传输渠道或其他适合该场景的信任锚来验证。

接收方收到文件，不等于获得了本地证明：

`TRANSFERRED（已传播） ≠ LOCALLY_APPLICABLE（本地适用） ≠ LOCALLY_SELECTED（本地已选择）`

来源已经支持的适应可以作为迁移候选进入接收方。接收方优先检查来源和本地真正重要的差异，不需要为了形式重新走完整个发现历史。

来源如果是 `HARMFUL` 或 `NOT_SUPPORTED`，仍然可以作为非常有价值的**负面证据**传播，但不能因为跨了一个 Host 就被包装成“成功适应”。

这让一个个体学到的东西可以加速整个族群进化，同时又不假装“一个环境成功就证明所有环境成功”。

## 9.9 重组与涌现

重组本身就是重要的变异生成器。

如果 A 和 B 分别有效，不能直接假设：

`A + B = A 的收益 + B 的收益`

组合后要观察：冲突、抵消、放大、新资源相互作用、涌现能力、新的授权/外部影响表面。

所以组合级验证同时也是组合级探索。正向涌现应该被当作证据记录，不能因为以前只关注失败就把它当成噪声；负向相互作用同样是真实结果。

## 9.10 进化过程中的治理收敛

不要因为“还能再检查一次”就无限递归检查。

只有当下一步有限检查真的可能改变重要决定时，才继续加治理。当已表示的决策关键问题已经解决或被诚实限定，而再检查只会重复已知信息时，就应该停止继续加治理。

参考语义结果：

`READY（可以行动） | NARROW_AND_PROCEED（缩小范围后行动） | EVIDENCE_NEEDED（需要新证据） | STOP_OR_ESCALATE（停止或升级）`

通用工具无法证明调用者有没有漏写 blocker（阻断因素）。因此参考工具必须明确输出自己的证据范围是 `REPRESENTED_INPUTS_ONLY（只基于已表示输入）`。它输出 `READY` 的真实含义只能是：**如果调用者已经完整表示了所有重要决策输入，那么按这些输入可以行动。**

## 9.11 参考工具

`tools/ena_evolve.py` 提供一个只依赖 Python 标准库的参考实现：

```text
init
observe
review
propose
experiment
evaluate
integrate
archive
export
import
closure
status
selftest
```

这个工具负责保存进化状态和证据边界。它故意不会自动执行任意 Host 自我修改、不会验证外部证据真假、不会证明授权真实、不会证明恢复一定有效、不会认证迁移包的真实来源，也不会因为调用者没有填写 blocker 就推断“真的不存在 blocker”。

Host 可以直接使用、修改、嵌入或完全替换它，只要更好的实现仍然满足这些性质。

> **先允许变异，让现实选择。**
>
> **不要崇拜工具；继续改进它。**
