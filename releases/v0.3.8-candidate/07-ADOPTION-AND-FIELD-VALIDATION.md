# 7. Adoption and Field Validation — v0.3.8-candidate.0

Status: `CANDIDATE / NOT_CURRENT / NOT_FROZEN / NOT_RELEASED`.

Released Current remains `v0.3.7 / CURRENT / FIELD_VALIDATION` under `../current/`.

v0.3.8 candidate.0 asks a practical successor question:

> Can ENA preserve the v0.3.7 semantic/operational protection while reducing adopter context burden, eliminating status narration drift, making enforcement classes explicit, preserving decision meaning across zh-CN, and strengthening conformance tests?

## Adoption is not universal proof

If this candidate is later released, adoption must bind to immutable effective content established by governed release lineage, not a mutable branch label or candidate self-description.

Use:

`WRITTEN -> LOADED -> INTERPRETED -> SALIENT -> APPLIED`

Do not skip states by narration. A file existing on disk, a configured router, or same-session readback does not prove future-session salience/application.

## Candidate.0 high-value tests

### Product/adoption surface

1. **Human entry economy** — a new adopter can understand what ENA is for and what to use from `ADOPTER-QUICKSTART.md` without reading research history.
2. **Agent entry economy** — a fresh Agent can use the Runtime Kernel + Cue Index without being told to preload the full package.
3. **Status coherence** — no hot/adopter surface can reverse adoption decisions through contradictory Current/candidate/freeze/release narration.
4. **Enforcement honesty** — an adopter can distinguish `MODEL_CUE`, `MACHINE_GUARD`, `EXTERNAL_CONTROL_REQUIRED`, and `FIELD_EVIDENCE_REQUIRED` without treating prompt prose as a hard boundary.
5. **Host freedom** — Host-native equivalents remain legitimate when they preserve the required property; ENA-private implementation names are not mandatory ontology.
6. **Cold-lineage discipline** — research/adjudication/history remain retrievable but are not ordinary runtime payload.

### Inherited operational behavior

7. **Concrete HOW reachability** — ordinary cue -> CUE-INDEX -> relevant HOW -> exact procedure/reference/Host mechanism without reading `research/`.
8. **Hot/cold economy** — cold HOW/reference libraries do not require permanent active loading.
9. **Reference optionality** — bundled references remain optional/default-off and do not become complete-adoption requirements.
10. **False-BLOCK controls** — `NOT_REQUIRED / NOT_APPLICABLE / WAIT / UNKNOWN` remain usable instead of every cue activating governance.
11. **Retrieval sufficiency** — stored/known/file-exists does not become retrieved/sufficient/applied.
12. **WAIT vs replay** — timeout/silence does not become blind consequential retry.
13. **Authority applicability** — harmless local work is not forced through unnecessary authority ceremony; consequential external authority still requires real Host/system basis.
14. **Effect lifecycle honesty** — intent/attempt/receipt/settlement remain distinct; cancel/rollback/compensation remain distinct.
15. **Recovery composition** — restored state does not imply complete history, reversed external effects, or restored mandate.
16. **Purpose-relative continuity** — continuity is solved for the actual decision rather than universal SAME_AGENT metaphysics.
17. **Standing without sovereignty** — material objection can affect review without granting execution/veto/policy authority.
18. **Evidence dependency** — correlated copies do not manufacture independent confirmation.
19. **Control retirement** — quietness/age/no-incident does not become retirement proof; replacement/coverage/lineage/reactivation evidence matters.
20. **Commons receiver autonomy** — source selection/popularity does not become receiver-local proof.
21. **Local-not-universal fitness** — local survival/success remains environment-scoped and does not become universal or moral correctness.
22. **Composition** — valid/improved components do not establish the composed outcome when interaction can change the decision.
23. **Memory metabolism** — raw episode accumulation is not treated as equivalent to compiled/retrievable long-lived competence.
24. **Projection/compaction** — factually true summaries do not become material-use-ready when decision dependencies were omitted.
25. **Current v2 tooling regression** — inherited v2 record/packet behavior remains self-contained and does not mint receiver-local selection from source selection.

### Language

26. **zh-CN hot-surface fidelity** — decision-bearing guardrails present in the English semantic source are not silently dropped from the supported Chinese hot surface.
27. **Route reachability** — zh-CN users can reach the same decision-relevant OA routes, including runtime salience, memory metabolism and projection/compaction.
28. **Bilingual behavior** — paired semantic fixtures should yield aligned decision properties/routes under actual model/Host tests; fixture presence itself is not proof.

### Economics

29. **Operational economics** — routing, references, evidence machinery, controls and new product surfaces must earn their maintenance/context cost.

The numbered list is organization, not an ontology or required test-count threshold.

## Machine evidence boundary

Machine checks may establish represented consistency, path closure, schema/validator behavior, deterministic tool invariants, fixture structure, or package identity within their exercised scope.

They do not prove external evidence truth, authority reality, receipt/settlement reality, recovery reality, universal Host fitness, future natural salience, or bilingual behavioral equivalence.

`ENFORCEMENT-MAP.yaml` is the candidate's explicit control/evidence classification surface.

## Field evidence that created this successor

Issue #201 is treated as decision-bearing field evidence because it reported both concrete file defects and observed fresh-context consequence: correct routing could still end in the wrong adoption decision because stale narration overrode release reality.

External usability/projection review independently exposed that local ENA semantics can be understandable while the whole package is still misread as research/legal prose rather than a deployable method + rules + test surface.

Neither input is automatically sovereign. Both are evidence that materially changed candidate scope.

## Field-validation boundary

Candidate assembly and validation do not make candidate.0 Current.

If later released, field findings must still bind to the exact effective-content identity plus actual Host/model/language/configuration where those factors can change the decision.

> **The product test is not whether ENA can explain itself at length; it is whether adopters can use the right protection with the least sufficient context and verify the claims they rely on.**
